# K-Journey PRD v2.0 — 생활 준비와 문화 여정을 한 제품으로

- 상태: 현재 제품 정본
- 기준일: 2026-08-02
- 제품 결정: `DEC-040`
- 구현 결정: `docs/adr/0036-unified-journey-experience.md`
- 과거 기록: `K-Journey_PRD_v1_1_KR.md`는 역사 참고용이며 충돌 시 이 문서가 우선한다.

## 1. 제품 정의

K-Journey는 한국에 오는 교환학생이 놓치면 곤란한 행정 절차를 끝내면서, 한국에서 해보고 싶은 경험을 모아 자신만의 8폭 병풍을 완성하는 로컬 우선 앱이다.

제품은 서로 역할이 다른 두 축을 한 흐름으로 연결한다.

1. **Essentials**: 사용자 조건과 일정에 따라 필요한 행정 체크리스트를 보여 준다.
2. **Culture**: 4개 시기의 문화 미션 55개와 사용자가 만든 Want-to 항목을 제공한다.

문화 미션과 Want-to 완료는 총 48개의 순간으로 집계되어 6개마다 병풍 한 폭을 연다. 행정 과업은 실수 방지가 목적이므로 이 보상 집계에 섞지 않는다.

## 2. 문제와 기회

교환학생 준비 도구는 보통 서류 목록에 머물러 사용 동기가 약하고, 여행·문화 앱은 중요한 행정 기한을 책임지지 않는다. K-Journey는 두 문제를 다음 관계로 푼다.

- 행정 축이 “한국 생활을 시작할 수 있게” 만든다.
- 문화 축이 “한국 생활을 계속 기록하고 싶게” 만든다.
- 병풍이 분산된 완료를 하나의 진행 서사로 묶는다.

## 3. 대상 사용자와 핵심 작업

### 3.1 1차 사용자

한국 대학으로 한 학기 또는 두 학기 교환을 오는 외국인 학생. 자신의 정확한 비자·주거·보험·학교 조건을 모두 알지 못할 수 있고, 한국어 행정 정보 탐색에 부담을 느낀다.

### 3.2 사용자가 해결하려는 일

- 내 조건에서 지금 해야 하는 행정 일을 빠르게 찾고 싶다.
- 날짜나 조건이 불명확할 때 무엇을 먼저 확인할지 알고 싶다.
- 한국 생활에서 해볼 일을 발견하고 내 목록을 만들고 싶다.
- 완료한 순간이 사라지지 않고 시각적 결과물로 남기를 원한다.

## 4. 정보 구조

| 1차 탭 | 목적 | 핵심 내용 |
|---|---|---|
| Journey | 오늘의 행동 결정 | `Essentials / Culture` 전환, 시기별 우선 행동 |
| Byeongpung | 진행 결과 확인 | 8폭 진행도, 다음 해금까지 남은 순간, 저장·공유 |
| Want to | 개인화된 경험 계획 | 6개 템플릿, 사용자 버킷과 항목 |
| More | 보조 정보와 설정 | 캠퍼스, 갤러리, 긴급 정보, 프로필·시대·내보내기 |

Journey의 기본값은 Essentials다. 마지막 선택은 기기 로컬에 저장한다.

## 5. 핵심 흐름

### 5.1 첫 사용

1. 체류 날짜와 조건을 입력하거나 모르는 값을 그대로 둔다.
2. 앱은 사실을 추정하지 않고 `확인 필요` 또는 날짜 설정 안내를 보여 준다.
3. 첫 홈에서 행정 준비와 문화 여정의 관계를 짧게 설명한다.
4. 사용자는 즉시 첫 행정 과업 또는 첫 문화 미션으로 이동할 수 있다.

### 5.2 행정 체크리스트

- 조건 규칙이 과업의 `available`, `review_required`, `blocked`, `locked_permanent` 상태를 계산한다.
- 날짜가 없으면 큰 경고 두 개를 반복하지 않고 하나의 날짜 설정 카드로 안내한다.
- 사용자의 실제 상태와 적용 조건은 완료 상태와 분리한다.
- 금액, 기한, 기관 요구사항은 변경될 수 있으므로 출처·확인일·최종 확인처를 함께 관리한다.

### 5.3 문화 미션

- 4개 시기, 4개 카테고리, 총 55개 정적 미션을 제공한다.
- 현재 시기의 첫 미완료 미션을 `Start here` 카드로 먼저 제시한다.
- 상세 화면은 팁뿐 아니라 `Complete when` 기준과 정보 변경 가능성 고지를 보여 준다.
- 완료/취소는 사용자가 직접 결정하며 위치·사진 증명을 요구하지 않는다.

### 5.4 Want-to

- 템플릿은 실제 민화 이미지를 미리보기로 보여 주고 선택 시 생성 화면에 선반영한다.
- 항목 원문은 분석 이벤트에 보내지 않는다.
- 완료된 항목은 문화 미션과 같은 병풍 진행 합계에 들어간다.

### 5.5 병풍

- 3개 시대 × 8폭이며 한 시대를 선택해도 진행 데이터는 유지한다.
- 총 48개의 문화 완료를 6개 단위로 나눠 8폭을 순서대로 연다.
- 잠긴 그림도 실루엣과 모티프를 알아볼 수 있어야 하며, 열린 정도와 다음 목표를 텍스트로 함께 제공한다.
- 8폭은 독립 포스터 모음이 아니라 하나의 접이식 병풍으로 읽히도록 프레임·이음새·연결 배경을 사용한다.

## 6. 데이터·개인정보 경계

- 계정과 로그인을 요구하지 않는다.
- 프로필, 조건, 완료, Want-to 내용은 현재 기기의 MMKV에만 저장한다.
- 앱 삭제·기기 분실 시 복구를 보장하지 않는다.
- 텍스트 내보내기는 일부 행정 데이터의 사람이 읽는 사본이며 앱 복원 파일이 아니다.
- PostHog 키가 설정된 빌드에서만 익명 제품 이벤트를 전송한다. 자유 입력, 이메일, 이름, 세부 조건 값은 보내지 않는다.
- 세션 리플레이는 별도 동의·마스킹 검증 전까지 비활성화한다.

세부 계약은 `docs/LOCAL_DATA_LIFECYCLE.md`를 따른다.

## 7. 성공 지표

현재 배포본은 분석 키가 없으면 계측하지 않는다. 아래 수치는 목표이자 향후 측정 정의이며 현재 성과를 뜻하지 않는다.

| 목표 | 지표 | 초기 판단 기준 |
|---|---|---|
| 첫 행동 도달 | 온보딩 완료 후 첫 행정/문화 상세 진입 | 중앙값 2분 이내 |
| 행정 유용성 | 적용 가능한 과업을 1개 이상 완료한 사용자 비율 | 7일 내 60% 이상 |
| 경험 활성화 | 문화 미션 또는 Want-to 첫 완료 | 7일 내 45% 이상 |
| 병풍 이해 | 병풍 방문 후 다음 완료 행동으로 이동 | 방문 세션의 25% 이상 |
| 통합 축 사용 | 7일 내 Essentials와 Culture를 모두 사용 | 활성 사용자의 35% 이상 |

정확한 이벤트와 실험 기준은 `docs/MEASUREMENT_AND_EXPERIMENTS.md`에 둔다.

## 8. 품질 수용 기준

- 390×844 모바일에서 각 홈의 첫 실행 가능 항목이 초기 화면 또는 한 번의 짧은 스크롤 안에 보인다.
- 1024px 이상 웹에서 앱 본문은 최대 760px 셸 안에 읽기 좋은 폭으로 유지된다.
- 탭, 전환, 저장·공유 버튼은 최소 44×44pt이고 상태를 접근성 라벨로 전달한다.
- 텍스트 확대, 키보드 탐색, Reduce Motion, 4.5:1 본문 대비를 확인한다.
- 병풍 24개와 템플릿 6개 원본의 앱 포함 용량은 합계 20MB 이하를 목표로 한다.
- `npm run check`와 웹 정적 빌드가 통과해야 한다.

## 9. 현재 범위와 다음 범위

### 현재 포함

- 로컬 온보딩과 조건 기반 행정 체크리스트
- 문화 미션 55개
- Want-to 템플릿·사용자 항목
- 3개 시대의 8폭 병풍
- 캠퍼스·긴급 정보·설정·부분 내보내기

### 아직 포함하지 않음

- 계정, 클라우드 동기화, 기기 간 복원
- 사진 업로드와 공개 소셜 피드
- 자동 위치 인증
- 운영자가 앱 밖에서 콘텐츠를 수정하는 CMS
- 실제 사용자 인터뷰 결과를 가장한 주장

## 10. 비인터뷰 검증 계획

실제 인터뷰 전에도 다음은 수행한다.

2. 초행 교환학생 시나리오 기반 인지적 워크스루
3. 날짜 미상·조건 미상·오프라인·재설치 등 엣지 케이스 검증
4. 모바일/웹 반응형·접근성·성능 회귀 검사
5. 5초 테스트, 첫 클릭 테스트, 카드 소팅용 프로토콜 준비
